# Lead CRM — контекст проекта для AI

Базовая CRM для лидов: заявки приходят с формы на сайте, менеджеры ведут их по статусам,
администратор распределяет лиды и управляет пользователями.

## Правила работы

1. **Думать до кода** — сначала понять задачу и данные, потом писать.
2. **Простота** — минимальное решение, без абстракций «на вырост».
3. **Хирургические правки** — меняется только то, что нужно для задачи; соседний код не переписывается.
4. **Каждая правка заканчивается проверкой** — `php tests/run.php` и ручной прогон затронутого сценария.
5. Комментарии, интерфейс и коммиты — на русском.

## Стек

- **PHP 8.4+**, Yii2 (basic-структура), MySQL 8 (в тестах — SQLite).
- Интерфейс: серверные шаблоны Yii2, Bootstrap 5 и Chart.js с CDN, без фронтенд-фреймворков.
- Деплой: Docker Compose (php-fpm + nginx + mysql).

## Структура

- `models/User.php` — пользователи и роли (`admin`, `manager`), IdentityInterface.
- `models/Lead.php` — лид; **единственное место**, где описаны статусы и разрешённые переходы.
- `models/LeadHistory.php` — история изменений; пишется автоматически из `Lead::afterSave()`.
- `models/LeadComment.php` — комментарии к лиду (добавление тоже попадает в историю).
- `models/LeadSearch.php` — фильтры и поиск; здесь же ограничение видимости для менеджера.
- `components/LeadAssigner.php` — автораспределение новых лидов (наименее загруженный менеджер).
- `controllers/ApiController.php` — REST API: `POST /api/leads` (приём лида), `GET /api/me` (проверка токена).
- `controllers/TokenController.php` + `views/token/index.php` — раздел «API»: персональные токены и документация.
- `controllers/LeadController.php`, `UserController.php`, `SiteController.php` — интерфейс.

## Ключевые решения (не пересматривать)

- **Роли — колонка `user.role`**, а не таблицы RBAC: ролей две, иерархии нет.
- **Менеджер видит только своих лидов.** Ограничение применяется в двух местах:
  `LeadSearch::search()` (списки, дашборд) и `LeadController::findModel()` (карточка).
  Чужой лид отдаёт 404, а не 403 — не раскрываем, что такой ID существует (защита от IDOR).
- **Статусы и переходы** описаны только в `Lead::TRANSITIONS`. Любая смена статуса идёт через
  `Lead::changeStatus()`. Финальные статусы (`success`, `rejected`) может вернуть в работу только админ.
- **История пишется в `afterSave`** по списку `Lead::TRACKED`; автор — текущий пользователь,
  для API — `null` (в интерфейсе «Система»).
- **API: персональные токены** (`crm_…`) у каждого пользователя; в БД хранится только SHA-256 хеш,
  токен показывается один раз. Лид по токену менеджера назначается ему; по токену админа — `manager_id`
  или автораспределение; общий токен сайта (`CRM_API_TOKEN`) — автораспределение.
  Менеджер управляет только своим токеном и видит краткую инструкцию; полная документация — у админа.
- **CORS открыт** (`CRM_API_ORIGINS=*`): доступ даёт только токен в заголовке, cookie не используются.
  CSRF для API отключён. Honeypot-поле `website` отсекает простых ботов.
- **Дубли:** заявка с тем же номером (сравнение по последним 9 цифрам) за 24 часа не создаёт новый лид,
  а добавляет комментарий к существующему.
- Телефон хранится нормализованным (только цифры и ведущий `+`).
